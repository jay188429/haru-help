# 하루상점 고객센터 결과 문서 (M47) — 1~2쪽, PDF

기록(`score-sheet.md`)에 있는 값만 쓴다. 비어 있으면 「미완료」로 두고 5절에 이유를 적는다.

## 1. 문제 · 대상
- 대상: 하루상점 손님. 배송 · 교환 · 환불 · 포인트 같은 반복 질문에 사람이 매번 답해야 한다.
- 문제: 안내문이 흩어져 있어 답이 사람마다 달라지고, 재고 · 주문처럼 실시간 정보는 안내문만으로 답할 수 없다.

## 2. 해결 방식과 AI 적용점
| 하는 일 | 코드 | AI | 사람 |
|---|---|---|---|
| 안내문 검색 (RAG) | 안내문 40장을 임베딩해 저장 · 가까운 것 찾기 | 임베딩 · Re-ranking · 근거(문서 ID)를 붙인 답 | 안내문 작성 · 추가 |
| 도구 호출 (Agent) | 안내문 검색 · 내 주문 · 재고 · 사람에게 넘기기 네 도구, 최대 3번 | 어느 도구를 쓸지 고르기 | 넘어온 티켓에 답하기 |
| 가드레일 | 담당자만 안내문 · 티켓 접근, 보안 규칙 | 쇼핑 밖 질문 · 지시 무시 요청 거절 | 거절 기준 정하기 |
| 평가 | 평가 세트와 CI(eval-ci) | 심판 모델(LLM-as-judge) | 심판 결과를 직접 대조 |

## 3. 구현 결과
- 공개 주소: https://haru-help-3b683.web.app (관리 화면 `/admin.html`)
- 근거가 붙은 답: 예) 「택배는 보통 언제쯤 받아요?」 → 배송 안내 + (근거: k01, k03)
- 도구로 답한 예: 「원목 도마 지금 살 수 있어요?」 → 재고 3개, 「편수냄비 남아 있어요?」 → 품절, 「제가 시킨 앞치마 어디쯤 왔어요?」 → 배송 중
- 올리면 학습되는 안내문: .txt 파일을 올리면 잘라서 임베딩해 저장. 「강아지 옷 얼마예요?」 → 18,000원 (근거: kb-new-items-1)
- 관리 화면: 담당자 권한, 안내문 넣기, 연습 상품 넣기, 안내문 올리기, 상담 티켓 표

## 5. 한계와 다음 단계
- 평가 세트가 작다(검색 15 · 도구 12 · 거절 8). 점수 1개 차이를 실력 차이로 읽으면 안 된다.
- 거절은 프롬프트로 하는 가드레일이라 새로운 우회 문장에는 뚫릴 수 있다.
- 모델이 없는 도구 이름을 만들 때가 있다(예: hando_to_human). 동작에는 영향이 없지만 화면에 그대로 보인다.
- 처음 배포 때 연습 상품 데이터가 빠져 재고 질문이 담당자에게 넘어갔다. 연습 상품 넣기 버튼을 만들어 해결했다.
- 못 한 미션 · 미완료: 낱말 겹침 기준 점수, CI 통과/실패 PR 비교, 심판과 사람 대조.

## (고도화 항목) 앞 프로젝트보다 무엇이 고도화됐나
- 낱말 겹침 검색 → 벡터 검색 + Re-ranking
- 정해진 답 → 도구를 골라 쓰는 상담 + 사람에게 넘기기
- 사람이 보는 눈대중 평가 → 평가 세트 · 심판 모델 · CI
